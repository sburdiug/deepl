# ЛР4. FP32 проти INT8

Експортували ResNet‑18 з ЛР3 (`frozen`, seed 3) в ONNX FP32 (opset 17, `dynamo=False`, змінний batch). Зробили дві версії статичної квантизації QDQ після навчання. Активації — QUInt8, ваги — QInt8, калібрування — MinMax. Єдина різниця між INT8-версіями — поканальні або потензорні ваги.

## Як перевірили

Використали поділ ЛР3. Train — 1200 зображень, сума імен 11 993 084. Test — 1502, сума 33 351 444. Калібрування — 200 зображень із відсортованого train за перестановкою з seed 0. Сума імен 1 921 470, кількості за класами `40 / 35 / 36 / 33 / 29 / 27` у порядку ЛР3. Калібрували по одному RGB-зображенню 160 × 160 із нормуванням ImageNet. На test залишили той самий порядок і перетворення, пакет 64.

PyTorch і ONNX FP32 передбачили однакові класи для всіх 1502 зображень. Macro-F1 збігся з ЛР3 (0,89191262). Максимальна різниця логітів — `1,14 × 10⁻⁵`. У графі 20 Conv і 0 BatchNormalization, бо в `eval()` їх об’єднано зі згортками. Експорт тривав 0,756 с, підготовка графа 0,641 с, квантизація з калібруванням 4,070 с для поканальної і 13,659 с для потензорної.

## Дослід із потензорними вагами

Прогноз записано 20.11.2026 після аналізу FP32-ваг і до запуску квантизації. Медіанне відношення діапазонів `r = 3,445` відповідає втраті приблизно `1,78` біта, а в першій згортці `r = 6,668`. Очікую, що потензорна квантизація знизить згоду з FP32 порівняно з поканальною. Очікую малу зміну macro-F1 і відсутність помітної зміни accuracy за парним правилом з умови: частина змінених передбачень виправить помилки FP32, а частина створить нові.

Для кожної згортки `α` — найбільша абсолютна вага каналу, `r = max(α) / median(α)`. Найбільші `r` отримали в `/conv1/Conv` (6,668), `/layer3/layer3.1/conv2/Conv` (5,896) і `/layer3/layer3.0/downsample/downsample.0/Conv` (4,921). Медіана за 20 згортками — 3,445, тобто `log₂(r) ≈ 1,78` біта.

## Результати

| Варіант | Macro-F1 | Accuracy | Згода з FP32 | b / c | Δ accuracy ± SE |
| --- | ---: | ---: | ---: | ---: | ---: |
| FP32 | 0,89191 | 0,89015 | 100,00% | 0 / 0 | 0 ± 0 |
| INT8, поканальна | 0,88975 | 0,88815 | 99,00% | 6 / 9 | −0,00200 ± 0,00258 |
| INT8, потензорна | 0,89110 | 0,88948 | 98,67% | 9 / 10 | −0,00067 ± 0,00290 |

`b` — помилки FP32, виправлені INT8, `c` — нові помилки INT8. `Δ = (b − c)/n`, `SE = √(b + c)/n`, де `n = 1502`. В обох варіантах `|b − c| ≤ 2√(b + c)`, тому зміна accuracy в межах шуму. Парна SE поканальної INT8 (0,00258) у 3,13 раза менша за SE accuracy FP32 (0,00807), бо спільні відповіді скорочуються в різниці. Прогноз справдився. Потензорні ваги дали меншу згоду, а macro-F1 змінилася мало. Згода враховує кожну зміну класу, а виправлені й нові помилки можуть компенсуватися.

Затримку виміряли на i5‑14600KF, Windows 11 (26200), Python 3.12.10, PyTorch 2.9.0+cu128, ONNX 1.20.1, ONNX Runtime 1.24.4. Сесії заздалегідь створено з `CPUExecutionProvider`, стандартною оптимізацією, одним intra-op і одним inter-op потоком. Вхід — перше test-зображення `22076.jpg`, batch 1. У кожному з трьох раундів спочатку FP32, потім INT8, по 20 прогрівів і 100 замірів одного `session.run`. ПК працював від мережі, фонові програми окремо не перевіряли.

| Варіант | Файл, МБ (10⁶ байтів) | p50, мс | p95, мс | p50 за раундами, мс |
| --- | ---: | ---: | ---: | --- |
| FP32 | 44,71 | 12,960 | 14,262 | 12,885 / 12,801 / 13,142 |
| INT8, поканальна | 11,30 | 4,251 | 4,969 | 4,286 / 4,190 / 4,247 |

**Висновок.** Файл INT8 менший у 3,96 раза, p50 нижчий у 3,05 раза, p95 — у 2,87 раза. Діапазони p50 за раундами не перетинаються. За згоди 99,00% і різниці accuracy в межах шуму поканальна INT8 підходить для цієї задачі на цьому CPU. За моделлю даху важливі і трафік пам’яті, і обчислення. AVX2 VNNI підтримує цілочисельні добутки, а зменшення ваг діє лише на частину роботи графа. uv run --project lab4 --locked python -m lab4.run --model lab3/lab3_model.pt --split lab3/split.csv --data data/intel
